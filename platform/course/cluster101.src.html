Module 1

Meet the cluster

A cluster is several ordinary computers wired together and managed as one. You log in to one of them – the head node – and it sends your work to the compute nodes. All machines see the same files, so results appear in your folder no matter which node did the work.

The example cluster is named after The Croods: grug leads (head node), gran remembers (backups), and eep, ugga, thunk and guy do the work.

Head node

Where you log in, edit files and submit jobs. Keep heavy calculations off it – it serves everyone.

Compute nodes

Do the actual work. You never log in to them directly; Slurm sends jobs there.

Shared storage

/home (your files) and /shared (software, templates, models) look the same on every node.

Words you will meet

Thread (or CPU): one lane of work. Our cluster has 44. Memory: how much data a job can hold at once; every job asks for an amount and gets stopped if it uses more. Job: a script you hand to the scheduler. Slurm: the scheduler – it queues jobs and starts them when threads and memory are free.

Module 2

How a job runs

You never start calculations by hand on a compute node. You describe the work in a job, Slurm finds a free spot, runs it, and the results land in your folder.

Anatomy of a job script

Every template contains a small script like this. The #SBATCH lines are a request to Slurm; everything below them is ordinary shell commands.

#!/bin/bash
#SBATCH -J dock                # job name shown in the queue
#SBATCH -c 1                   # threads per task
#SBATCH --mem=1G               # memory; exceeding it stops the job
#SBATCH -t 24:00:00            # time limit (default 1 h, max 7 days)
#SBATCH -o logs/%x_%A_%a.out   # where screen output goes
source /shared/apps/sbio/bin/activate   # load the science software
vina --receptor ... --ligand ... --out results/poses/...

Every template works the same way

01_docking/
├── README.md       what it does, how to read results
├── settings.env    the few things you change

├── submit.sh       run this – it submits everything
├── logs/           job output, look here if something fails
└── results/        tables, plots, structures
Module 3

Thinking in parallel

The cluster is not a faster computer – each thread is about as fast as a good desktop. Its power is doing many things at once. A virtual screen of 5 000 ligands is 5 000 independent dockings; 44 threads run 44 of them side by side. Slurm calls this a job array.

busy threadfree thread
on one thread (a laptop, one after another)
on the whole cluster (44 at once)

What parallelises well here – and what doesn’t

WorkloadShapeFit for this cluster
Docking screens, mutation scans, pocket searches, all-vs-all comparisonsmany small independent tasksExcellent – uses all 44 threads
Molecular dynamicsone tightly coupled calculationGood on one node – run replicas side by side; a 1 Gb/s network makes one simulation across nodes slower
Protein language models (ESM)matrix maths on CPUGood for up to ~1000 residues per sequence
AlphaFold, RFdiffusion, large deep-learning trainingneeds GPUs and huge databasesNot practical – use a GPU service
Module 4

The science

Six ready-made workflows cover the core questions of structural bioinformatics: where can a molecule bind, what binds, which mutations matter, and how a protein moves.

Docking & virtual screening

01_dockingAutoDock Vina

Question: which small molecules fit a protein pocket, and how? Vina tries thousands of poses of each ligand inside a search box and scores each one (kcal/mol, more negative = tighter predicted binding).

Docking scores rank; they don’t measure affinity. Always inspect top poses and follow up with MD or experiment.

Pocket detection

06_pocketsfpocket

Question: where on a protein could a drug bind? fpocket fills cavities with virtual spheres, clusters them into pockets and estimates how druggable each is (0–1). The pocket centre goes straight into the docking box.

StructurePocketDruggabilityVolume Å³

Real result: the top HIV protease pocket (druggability 0.93) sits exactly where indinavir binds – found without being told.

Mutation effects from sequence

04_esm_scanESM-2 language model

Question: which mutations will a protein tolerate? ESM-2 learned the “grammar” of proteins from millions of natural sequences. Hide one residue, ask the model what belongs there, and compare the mutant’s probability with the original’s. Strongly negative = evolution rarely allows this change.

Stability changes (ΔΔG)

02_foldx_scan05_rosetta_ddg

Question: does a mutation make the folded protein less stable? Both tools build the mutant into the 3D structure and compare energies. FoldX is fast enough to scan every position; Rosetta is slower but more careful – use it on the shortlist.

Molecular dynamics

03_mdGROMACS

Question: how does the protein move, and does a mutation or ligand change that? MD puts the protein in a box of water and salt and follows every atom’s motion in 2-femtosecond steps. The template builds the system, equilibrates it, runs production and draws the standard plots.

Structure comparison

07_similarityUS-align

Question: which structures share a fold? US-align superimposes each pair and reports a TM-score: above 0.5 means the same fold, below 0.3 means unrelated. Useful for clustering models, comparing predictions with experiment, or grouping homologues.

Module 5

Hands-on labs

Do these in order. Each uses the example data that comes with the template, so nothing needs preparing.

Before you start: open the portal

  • On the head node: open Firefox and go to http://localhost:8080.
  • From the laptop on the cluster switch: in a terminal run ssh -L 8080:localhost:8080 yourname@10.0.0.1, leave it open, then browse to http://localhost:8080.
  • Log in with your cluster username and password. No account? An admin runs sudo cluster-add-user yourname.

Lab 1 · Hello cluster 2 min

  • New job → Hello cluster → Submit job.
  • Click Cluster in the top bar: watch threads light up on four nodes.
  • Back in My jobs, open the job and click results/nodes.tsv.

You should see: four rows (eep, ugga, thunk, guy) with “ok” for Vina and GROMACS.

Lab 2 · Dock your own molecule 10 min

  • Find a SMILES string for a molecule (e.g. on PubChem, before coming to the lab).
  • Make a text file my.smi containing one line: SMILES name.
  • New job → Docking. Change Ligands to my.smi, upload the file and tick keep example files.
  • When finished, open results/ranking.tsv, then click 3D next to your pose.

Question to think about: does your molecule beat indinavir (−10.4)? Does its pose fill the same pocket?

Lab 3 · Which mutations break a protein? 5 min

  • New job → Variant effect scan. Paste your protein’s sequence into a FASTA file and upload it (or keep ubiquitin).
  • Open the heatmap plot and results/<name>.tsv (sorted, most harmful first).

Question: are the most harmful positions buried in the structure, or at a binding site?

Lab 4 · Watch a protein move 25 min run

  • New job → Molecular dynamics → submit with the defaults (ubiquitin, 1 ns, guy).
  • While it runs, look at the Cluster page: guy shows all 20 threads busy.
  • Open the RMSD and RMSF plots when it finishes.

For real projects: 3 replicas of ≥100 ns each, wild type and mutant side by side.

Lab 5 · The terminal way 10 min

ssh yourname@10.0.0.1
cp -r /shared/template/06_pockets ~/jobs/my-pockets
cd ~/jobs/my-pockets
./submit.sh
squeue --me                          # wait until it disappears

The portal and the terminal share the same ~/jobs folder: this job also appears in My jobs.

Module 6

Good practice & troubleshooting

Be a good neighbour
  • No heavy work on the head node – submit a job.
  • Big arrays: add %20 (e.g. --array=1-5000%20) to leave room for others.
  • Ask for the time and memory you need, not the maximum.
  • Delete trajectories and intermediate files you won’t use.
Your data
  • /home is copied to gran as a backup.
  • The cluster is offline: bring input files on the laptop or a USB stick.
  • Download results with Download all in the portal, or scp.
  • New software is added by an admin into /shared/apps.

Module 8

Glossary

Array job
One submission that runs the same script many times with a different task number – how screens and scans spread over the cluster.
Checkpoint
A file saved during a long run so it can continue after being stopped.
Compute node
A machine that runs jobs (eep, ugga, thunk, guy).
Druggability
fpocket’s estimate (0–1) that a pocket can bind a drug-like molecule.
ΔΔG
Change in folding stability caused by a mutation; positive = destabilising.
Head node
The machine you log in to; runs Slurm, the portal and shared storage.
Masked marginal
ESM scoring method: hide a residue, compare the model’s probabilities for mutant and wild type.
NFS
Network file system – why /home is the same on every machine.
Pose
One predicted position and shape of a ligand in a pocket.
RMSD / RMSF
Average deviation of a structure from a reference over time / per-residue flexibility.
Slurm
The scheduler: queues jobs and starts them on free resources.
Thread (CPU)
One unit of computing; the cluster has 44.
TM-score
Structural similarity from 0 to 1; above 0.5 = same fold.
