PBS 101 for CHPC

You already run jobs on the lab cluster with Slurm. The CHPC Lengau cluster uses PBS Pro. The ideas are identical – only the words change. This course maps one onto the other so you can move a working lab job to CHPC in minutes.

Slurmlab cluster · sbatch
PBS ProCHPC Lengau · qsub
1 lineyou must add on CHPC: #PBS -P
Check before you run. CHPC queue names, limits and module names change over time. The values here are a guide; the source of truth is the CHPC wiki (wiki.chpc.ac.za) and qstat -Q on Lengau.
Module 1

Same ideas, new words

Both schedulers do the same job: you describe work in a script, it waits in a queue, it runs on compute nodes.

Module 2

The job script, side by side

The biggest change is how you ask for CPUs and memory. PBS asks for chunks: “give me N pieces, each with this many CPUs and this much memory”.

Slurm · lab cluster
#!/bin/bash
#SBATCH -J md
#SBATCH -N 1
#SBATCH -c 24
#SBATCH --mem=60G
#SBATCH -t 24:00:00
#SBATCH -o logs/%x_%j.out

# starts in the submit folder
source /shared/apps/sbio/bin/activate
gmx mdrun -ntomp $SLURM_CPUS_PER_TASK -deffnm md
PBS Pro · CHPC
#!/bin/bash
#PBS -N md
# project code + queue (no comments at the end of #PBS lines)
#PBS -P CBBI1234
#PBS -q smp
#PBS -l select=1:ncpus=24:mem=60gb
#PBS -l walltime=24:00:00
#PBS -j oe
#PBS -o md.log

cd $PBS_O_WORKDIR          # starts in ~ otherwise!
module load chpc/BIOMODULES gromacs
gmx mdrun -ntomp $NCPUS -deffnm md

Reading a select line

-l select=2:ncpus=24:mpiprocs=24:mem=100gb
          │  │         │           └ memory per chunk
          │  │         └ MPI ranks per chunk (for mpirun)
          │  └ CPUs per chunk
          └ number of chunks (≈ nodes)

Module 4

Lengau essentials

Log in

ssh you@lengau.chpc.ac.za
The login node is shared: edit and submit, don’t compute.

Project code

Every job needs -P with your research programme code (from your CHPC allocation). No code → job refused.

Software

module avail, module load chpc/BIOMODULES, then e.g. module avail gromacs.

Storage

WhereUse forNote
/home/$USERscripts, small filessmall quota
/mnt/lustre/users/$USERrun jobs here: inputs, trajectories, resultsfast and large, not backed up, old files may be purged

Copy results back to the lab cluster or your laptop when a project stage is done.

Queues (guide – confirm with qstat -Q)

QueueTypical useRough size / time
serial1 node, fewer than a full node of cores (docking tasks, analysis)up to 23 cores · 48 h
seriallongsame, longerup to 23 cores · 144 h
smpone full node (e.g. single-node MD)24 cores · 96 h
normalmulti-node MPI25–240 cores · 48 h
largebig MPI runs264+ cores · 96 h
bigmemjobs needing ~1 TB memory48 h
gpu_1 … gpu_4GPU MD, AlphaFold-type work10 CPUs per GPU · 12 h
testquick checks of a script3 h
Why this matters for us: the lab cluster has no GPUs. Develop and test on the lab cluster, then send the heavy runs (long GPU MD, large screens) to CHPC with the same script, translated.
Module 5

Worked conversions

1 · Docking array (from 01_docking)

Slurm
#SBATCH -J dock
#SBATCH --array=0-99
#SBATCH --mem=1G
#SBATCH -t 24:00:00
#SBATCH -o logs/%x_%A_%a.out

python prep_ligands.py input/lib.smi $tmp \
  $SLURM_ARRAY_TASK_ID 100
PBS Pro
#PBS -N dock
#PBS -P CBBI1234
#PBS -q serial
#PBS -J 0-99
#PBS -l select=1:ncpus=1:mem=1gb
#PBS -l walltime=24:00:00
#PBS -j oe

cd $PBS_O_WORKDIR
python prep_ligands.py input/lib.smi $tmp \
  $PBS_ARRAY_INDEX 100

Submit with qsub dock.pbs; watch with qstat -t 123[]. The docking commands themselves don’t change.

2 · Chained steps (prepare → run → collect)

Slurm
a=$(sbatch --parsable prep.sbatch)
b=$(sbatch --parsable --dependency=afterok:$a run.sbatch)
sbatch --dependency=afterany:$b collect.sbatch
PBS Pro
a=$(qsub prep.pbs)
b=$(qsub -W depend=afterok:$a run.pbs)
qsub -W depend=afterany:$b collect.pbs

qsub already prints just the job ID, so no --parsable. For an array, depend on it with afterok using the 123[] ID it prints.

3 · GPU molecular dynamics

#PBS -N md-gpu
#PBS -P CBBI1234
#PBS -q gpu_1
#PBS -l select=1:ncpus=10:ngpus=1
#PBS -l walltime=12:00:00
#PBS -j oe

cd $PBS_O_WORKDIR
module load chpc/BIOMODULES gromacs      # pick a GPU build: module avail gromacs
gmx mdrun -deffnm md -nb gpu -ntomp $NCPUS -cpi md.cpt   # -cpi: continue after the 12 h limit

Same restart idea as the lab 03_md template: resubmit and it continues from the checkpoint.
